# 通用代码审查

## 执行步骤

### 1. 理解上下文
- 先通读用户指定的代码文件或片段
- 如未指定文件，询问路径
- 了解代码的业务目的

### 2. 按维度审查
逐项检查，指出具体行号和原因：

#### A. 正确性
- 逻辑错误、边界条件遗漏
- 空指针/空值处理
- 异步竞态条件

#### B. 可读性
- 命名是否清晰
- 函数是否过长（超过 50 行建议拆分）
- 必要注释是否缺失

#### C. 可维护性
- 是否违反 DRY 原则
- 耦合度过高
- 魔法数字/字符串应提取为常量
- 异常处理是否完善

#### D. 性能
- 明显瓶颈（嵌套循环、重复计算）
- 内存泄漏风险
- 不必要的重渲染或重复请求

#### E. 安全性
- 用户输入是否校验/转义
- 敏感信息是否硬编码
- SQL 注入、XSS 等常见漏洞
